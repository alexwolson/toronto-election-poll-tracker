# Frontend rebuild — design spec (2026-08-21)

Rebuild the Toronto election frontend in-place to consume the four rebuilt
pipeline feeds, presented as a fail-closed, band-based **forecast** on the
existing broadsheet identity. Produced by a `/grill` design session; approved
2026-08-21.

## Sticky constraints (active all session)

- **In-place rebuild** — same repo, new `src/`; keep the deploy target and the
  existing `/wards` route paths.
- **Keep the stack**: Next.js 16.2.2 / React 19 / Tailwind v4 / recharts. Read
  `node_modules/next/dist/docs/` before any Next-specific code (AGENTS.md).
- **Static export** (`output: 'export'`), rebuilt on data change.
- **Keep + simplify** the broadsheet design system (`globals.css`, fonts,
  candidate palette, tokens); prune classes to what the new markup uses.
- **Bands & frequency phrases only — never a raw % number.** The feed nulls
  `probability` unless a band publishes; we present the band regardless.
- **ADRs never public.** Methodology is plain language, grounded in the data
  project's `CONTEXT.md` vocabulary. The `/how-it-works` page never links to,
  names, or exposes any ADR.
- **Private until certification; build against a certified fixture; launch =
  certified state.** The committed `data/processed` feeds stay dark
  (`field_certified: false`) until the maintainer flips the real flag.
- **Withheld quantities are hidden**, not shown.

## Routes

| Route | Shows |
|---|---|
| `/` | Mayoral forecast hero (lead + full band board + incumbent-defeat), compact polling snapshot, council entry |
| `/polls` | Trend chart (raw current-field points, **no modelled average**), per-poll archive, pollster sources |
| `/wards` | Council index: `base_rate_note` up top, sortable grid (most-exposed first), open seats flagged, **no win numbers** |
| `/wards/[ward_num]` | Ward detail: incumbent bio, prior result, exposure triggers, historical hints, ward polls |
| `/how-it-works` | Plain-language methodology + sources/attribution (Matt Elliott CDI, pollster registry). Absorbs the old `/sources`. **No ADRs.** |

## Key design decisions (from the grill)

| Q | Decision |
|---|---|
| Identity | "The Forecast," honesty-as-feature |
| Hero | Lead-first: favourite + frequency phrase → full band board (by prob. desc) → Incumbent-Defeat |
| Withheld quantities | **Hidden entirely.** Consequence: at launch the public sees no "Forecast Unavailable" state (Close-Result is the only withheld quantity and it is hidden). |
| Evidence tier | One plain-language evidence-basis line; **no** per-quantity "M3" codes/badges |
| Council | Attention markers (defeatability / exposure triggers), **never** probabilities |
| Chart | Raw current-field poll points, no modelled average (ADR 0044 retired it) |
| Visual identity | Keep + simplify the broadsheet system |

## Data layer

- New typed clients generated from the four-feed contract: mayoral forecast v1,
  mayoral polling v1, council race cards v2, manifest v1.
- Source resolution: a server-only loader reads a **local fixtures dir** when
  `FEED_LOCAL_DIR` is set (dev, against the certified fixture), else fetches the
  GitHub-raw base with the `NEXT_PUBLIC_API_URL` override (production), mirroring
  the old app's URL pattern.
- Contract gotchas handled: `band` is a **string label** (not an object);
  `election_cycle_id` differs across feeds (`toronto-2026` vs `toronto_2026`).

## Reuse / discard

- **Keep:** `globals.css` design system, fonts, candidate palette, masthead
  shell, the recharts line chart, the signal-range bar.
- **Discard:** every `*-api.ts`, `types/ward.ts`, and all pool-model /
  chow-pressure / coattail / win-probability components (8 of 16 already
  orphaned) — welded to the retired `model_snapshot.json` / `polls_snapshot.json`.

## Certified dev fixture

`fixtures/` holds the four feeds with `field_certified` flipped to true (the
certified state we build against). Regenerated by
`gen_certified_fixtures.py` (dev-only, not committed to the data project).
Certified state = 4/5 published:

- Chow win — 70–<90% "about 4 in 5"
- Bradford win — 10–<30% "about 1 in 5"
- Alexander win — 0–<5% "less than 1 in 10"
- Incumbent-Defeat — 10–<30% "about 1 in 5"
- Close-Result — withheld (hidden)

## TDD plan

Failing-test-first (vitest) on the pure logic: feed parsing/validation,
band → copy mapping, hero lead selection, withheld-hiding filter, polling trend
reshape, council sort/exposure logic. UI components get lighter render checks.

## Out of scope

Flipping the real `field_certified` flag (maintainer's action at certification);
any data-pipeline change; a public dark/holding page (not needed — private until
certified).
